# RMUC 2027 规则全流程实验对局（match_lab，非官方）

`rmuc2027-rules-lab-v2` 把仓库里所有带出处的 2027 规则模块装进**同一局、同一条 60 Hz 时钟**，
用内置脚本 AI 自动打满 7 分钟，确定性、可复算。它回答的是“这些规则组合起来是否自洽、会产生什么连锁反应”，
**不是完整官方比赛，也不能评估真实胜率**。原有各模式和规则模块的源码不受影响。

v2 新接入三个机制：**能量机关**（[energy_v1](../rules/rmuc2027_energy_v1/README.md)）、
**飞镖系统**（[dart_v1](../rules/rmuc2027_dart_v1/README.md)）、**雷达标记**（[radar_v1](../rules/rmuc2027_radar_v1/README.md)），
并增加随机种子与同配置多局统计。结果格式为 `rmuc2027-rules-lab-result.v2`，与 v1 的配置和结果不兼容。

```bash
bash tools/build.sh
python3 match_lab/cli.py run                       # 默认配置，中文摘要
python3 match_lab/cli.py example > lab.json        # 导出可编辑的配置
python3 match_lab/cli.py run lab.json --json       # 完整 JSON（事件、逐秒时间线）
python3 match_lab/cli.py run lab.json --frames 6 --json > replay.json   # 附 10 Hz 位置帧
python3 match_lab/cli.py run lab.json --seed 7     # 临时换一个种子
python3 match_lab/cli.py sweep lab.json --seeds 20 # 同一配置连续 20 个种子，输出胜负统计
```

配置严格校验（键必须完全一致、拒绝重复键、拒绝布尔冒充整数）：

| 键 | 取值 |
|---|---|
| `duration_s` | 1–420 |
| `credits` | 是否启用实验性的每秒末控制度结算 |
| `seed` | 0–999999999。只决定合成随机数：弹道散布、能量机关瞄准、飞镖与雷达的命中判定、能量机关点亮哪块装甲 |
| `red` / `blue`.`infantry` | 两台步兵各自的 `chassis`（`hp` 血量优先 / `power` 功率优先）与 `launcher`（`cooling` 冷却优先 / `burst` 爆发优先） |
| `sentry` | `auto` 自动哨兵 / `semi` 半自动哨兵 |
| `max_assembly` | 重装尝试的最高装配难度 0–3（四级难度不支持） |
| `gold_reserve` | AI 兑换时保留的金币 |
| `energy_accuracy` | 0–100，**合成**：击打能量机关时落在所瞄准的点亮模块上的弹丸比例；0 = 不打能量机关 |
| `dart_target` | `none`（飞镖不上场）/ `outpost` / `base-fixed` / `base-random-fixed` / `base-random-moving` / `base-terminal-moving` |
| `dart_accuracy` | 0–100，**合成**：飞镖命中所选检测模块的比例 |
| `radar_accuracy` | 0–100，**合成**：雷达坐标误差小于 0.8m 的比例，其余一半半准确、一半错误；0 = 雷达不上场 |

三个“命中率”代替的是本实验不模拟的瞄准、制导与视觉。它们决定“事实”（哪一环被击中、飞镖是否命中、坐标是否准确），
之后的一切由规则模块结算。

## 每个 tick 里发生了什么

1. **结算时间**：全队定时金币与装配金币流（economy_v1）、每台机器人的复活读条 / 读条复活 / 无敌与虚弱到期 /
   远程回血生效 / 整秒回血（lifecycle_v1）、哨兵姿态计时（buff_v1）、延迟到账的允许发弹量；
   能量机关的机会发放、2.5 秒 / 20 秒 / 增益到期（energy_v1）、飞镖闸门时间线（dart_v1）、
   雷达以 5 Hz 对每台对方地面机器人上报坐标并更新被标记进度 P、双倍易伤累计（radar_v1）。
2. **决策与移动**：脚本 AI 兑换弹量、远程回血、兑换立即复活、装配、安装 42mm、选择哨兵姿态，
   沿距离场寻路；底盘按功率上限限速，并按 10 Hz 结算缓冲能量（limits_v1）。
3. **阵地**：每台存活且非虚弱的机器人在区域内即为检测到，2 秒失效延迟（capture_v1），
   各方逻辑激活进入阵地生命周期（position_v1）：临时控制、5 秒离场恢复、前哨站击毁转换与 500 血重建。
4. **指挥**：有机会且有被标记的存活对手时触发雷达双倍易伤；飞镖有机会就开闸门，每次开启发射 2 枚，
   命中后按 dart_v1 结算：表 5-2 伤害（不受防御增益影响）、平分经验、对方能量机关增益暂时失效或被清除、
   移动目标命中时对方全部存活机器人按上限血量扣血、基地护甲展开、被命中建筑的增益点失效 30 秒。
5. **发射**：发射机构未锁定、非虚弱、有允许发弹量、热量不会越过上限时才开火；
   17mm 与 42mm 热量（limits_v1，等级变化时动态更新上限与冷却）；42mm 安装确认弹不计热量与伤害。
   执行能量机关任务的步兵在击打点对己方能量机关开火：照常消耗发弹量、计热量与发弹经验，
   每发由合成瞄准模型给出“击中哪个灯臂的第几环 / 未击中”，交给 energy_v1。
6. **弹丸与伤害**：命中按原始伤害表、攻击增益、防御 / 易伤 / 无敌 / 42mm 屏蔽结算（buff_v1）；
   大能量机关给全队攻击增益与热量冷却倍率，能量机关防御增益同时覆盖机器人、前哨站与基地；
   被对方雷达标记的机器人获得 15% / 20% 易伤，双倍易伤期间翻倍；
   基地在己方完全控制己方前哨阵地时 100% 防御；扣血进入攻击伤害账本（damage_v1）；
   经验按发弹、伤害、击毁结算，小能量机关增益期间额外 100%（每次增益全队至多 1200），
   等级受装配决定的全队上限约束（growth_v1）。
7. **成长**：升级立即加上限血量差值、更新热量参数；重装按装配阶段 400/450/500/600 血；
   42mm 解锁走三级装配或 `300 − M/50 − 2N/3` 秒时间路径。
8. **计分与判定**：每整秒按阵地控制给控制度（match_v1），基地被击毁立即按基地血量判胜，
   420 秒按控制度 → 攻击伤害 → 剩余血量 → 平局判定。

## 合成（SYNTHETIC）部分，非手册数据

- 场地：沿用原沙盒 12 × 7.6 m 点对称演示地图与三面墙；四个阵地矩形与目标区模式相同；
  补给区、装配区、前哨站 / 基地的位置和半径为自定。每个阵地只用一个矩形代表其全部增益点，
  未建模中央高地、堡垒、制高点、地形跨越增益点、空中系统。
- 能量机关挂在中央墙体的两侧，各方从墙前 1 m 见方的击打点射击；画面上飞向能量机关的弹丸只是示意，
  是否击中由瞄准模型决定：`energy_accuracy`% 落在所瞄准的点亮模块上，其余的十分之一打到未点亮的模块（导致激活失败），
  剩下的脱靶；径向误差在 `15 + 3 ×（100 − energy_accuracy）` 毫米内均匀分布，再按图 5-17 换算环数。
- 飞镖：飞行时间固定 1.5 秒，闸门完全开启 1 秒后发射第一枚、之后每 8 秒一枚，每次开启 2 枚；
  移动 / 随机目标的检测模块一律视为已静止；操作界面被遮挡只记为事件，不影响脚本 AI。
- 雷达：固定 5 Hz 上报；干扰波解析（密钥、难度等级）不模拟，双方雷达始终有效。
- 飞镖命中移动目标的按比例扣血按“飞镖类伤害”处理：无敌的机器人不受影响，不产生经验。
  飞镖伤害只给 §5.7.3 写明的经验，不按表 5-14 的装甲伤害另计经验。
- 被飞镖命中的前哨站增益点失效期间不提供回血 / 解除虚弱，基地增益点失效期间不提供 50% 防御 / 解除虚弱；
  阵地占领检测不受影响（阵地另含未建模的中央高地 / 堡垒增益点）。
- 机器人尺寸、最大速度、底盘峰值功率与速度的关系、弹速（低于初速上限）、射击间隔、弹道散布、
  6 m 感知距离、装配时长 15 秒 / 级、工作台在补给区内。
- AI 策略：步兵先补弹，后进攻对方前哨阵地，控制后推进对方基地，血量低于 30% 回补给区；
  哨兵守己方前哨阵地；重装先装配再装 42mm。步兵 2 在持有能量机关激活机会且有 50 发以上弹量时前往击打点触发并击打；
  指挥手有机会就开飞镖闸门、有机会就用双倍易伤。AI 很粗糙，只为驱动规则，不代表战术建议。
- 机器人依次移动，每个 tick 轮换先动的一方而角色顺序不变，指挥决策的先后同样轮换，避免固定的先手优势。
  寻路沿各目的地的距离场；双方在等距候选格之间的取舍互为点对称（v1 用固定扫描顺序，对称配置下蓝方明显占优，
  实测数字见 [docs/VERIFICATION.md](../docs/VERIFICATION.md)）。
  三分之一秒没有前进时，把其他机器人当作障碍重新规划一条个人绕行路线；绕行也走不通时向自己右侧让行。
  少数对局里仍会有机器人较长时间被堵住，导航只是为了驱动规则，不是路径规划的参考实现。

## 校验

- `tests/match_lab_tests.cpp`：7 种配置（含三套系统全关、强弱悬殊、移动目标飞镖）；两次独立运行输出逐字节一致，
  换种子结果不同；每个 tick 检查血量范围、步兵等级 = 经验对应等级且受上限约束、上限血量与性能表一致、
  战亡时读条长度 = 公式、金币 = 收入 − 支出、兑换上限、
  己方前哨阵地被己方完全控制时基地只可能被飞镖扣血（且不超过对方飞镖当刻造成的伤害）、基地阵地只由拥有方完全控制、
  完全控制的前哨阵地上前哨站必存活且归控制方、逐秒重算控制度与账本一致、
  攻击伤害账本 = 各机器人造成伤害 + 飞镖伤害之和、能量机关增益效果 = 表 5-22 / 小能量机关 25% 且被压制时为零、
  额外经验不超过每次增益 1200、雷达易伤 = 表 5-30（双倍期间 ×2）且对方无雷达时 P 恒为 0、
  飞镖发射 / 结算 / 在飞数量守恒、事件时间单调、任何机器人受阻的 tick 不超过全局的五分之一（防止交通死锁）；
  并确认各场景合计触发全部 31 类事件。
- `tests/test_match_lab.py`：配置严格校验、CLI 确定性、种子与系统全关、多局统计、帧数据与摘要输出、原生参数拒绝。
- `tests/test_lab_http.py`：`/api/lab/run` 与 `/api/lab/sweep` 的确定性和各拒绝路径。
- 确定性与构建优化级别无关的一次性验证结果见 [docs/VERIFICATION.md](../docs/VERIFICATION.md)。

## 多局统计

`sweep` 用同一配置、从 `seed` 起的连续种子各打一局，只汇总胜负、结束方式和平均基地血量 / 控制度 / 攻击伤害
（`rmuc2027-rules-lab-sweep.v1`；CLI 最多 200 局，本机接口 `/api/lab/sweep` 每次最多 50 局）。
各局之间只有合成随机数不同，统计描述的是这个合成模型，**不是真实比赛胜率**。
