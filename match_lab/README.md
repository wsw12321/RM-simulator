# RMUC 2027 规则全流程实验对局（match_lab，非官方）

`rmuc2027-rules-lab-v1` 把仓库里所有带出处的 2027 规则模块装进**同一局、同一条 60 Hz 时钟**，
用内置脚本 AI 自动打满 7 分钟，确定性、可复算。它回答的是“这些规则组合起来是否自洽、会产生什么连锁反应”，
**不是完整官方比赛，也不能评估真实胜率**。原有各模式和规则模块的源码不受影响。

```bash
bash tools/build.sh
python3 match_lab/cli.py run                       # 默认配置，中文摘要
python3 match_lab/cli.py example > lab.json        # 导出可编辑的配置
python3 match_lab/cli.py run lab.json --json       # 完整 JSON（事件、逐秒时间线）
python3 match_lab/cli.py run lab.json --frames 6 --json > replay.json   # 附 10 Hz 位置帧
```

配置严格校验（键必须完全一致、拒绝重复键、拒绝布尔冒充整数）：

| 键 | 取值 |
|---|---|
| `duration_s` | 1–420 |
| `credits` | 是否启用实验性的每秒末控制度结算 |
| `red` / `blue`.`infantry` | 两台步兵各自的 `chassis`（`hp` 血量优先 / `power` 功率优先）与 `launcher`（`cooling` 冷却优先 / `burst` 爆发优先） |
| `sentry` | `auto` 自动哨兵 / `semi` 半自动哨兵 |
| `max_assembly` | 重装尝试的最高装配难度 0–3（四级难度不支持） |
| `gold_reserve` | AI 兑换时保留的金币 |

## 每个 tick 里发生了什么

1. **结算时间**：全队定时金币与装配金币流（economy_v1）、每台机器人的复活读条 / 读条复活 / 无敌与虚弱到期 /
   远程回血生效 / 整秒回血（lifecycle_v1）、哨兵姿态计时（buff_v1）、延迟到账的允许发弹量。
2. **决策与移动**：脚本 AI 兑换弹量、远程回血、兑换立即复活、装配、安装 42mm、选择哨兵姿态，
   沿距离场寻路；底盘按功率上限限速，并按 10 Hz 结算缓冲能量（limits_v1）。
3. **阵地**：每台存活且非虚弱的机器人在区域内即为检测到，2 秒失效延迟（capture_v1），
   各方逻辑激活进入阵地生命周期（position_v1）：临时控制、5 秒离场恢复、前哨站击毁转换与 500 血重建。
4. **发射**：发射机构未锁定、非虚弱、有允许发弹量、热量不会越过上限时才开火；
   17mm 与 42mm 热量（limits_v1，等级变化时动态更新上限与冷却）；42mm 安装确认弹不计热量与伤害。
5. **弹丸与伤害**：命中按原始伤害表、防御 / 易伤 / 无敌 / 42mm 屏蔽结算（buff_v1）；
   基地在己方完全控制己方前哨阵地时 100% 防御；扣血进入攻击伤害账本（damage_v1）；
   经验按发弹、伤害、击毁结算，等级受装配决定的全队上限约束（growth_v1）。
6. **成长**：升级立即加上限血量差值、更新热量参数；重装按装配阶段 400/450/500/600 血；
   42mm 解锁走三级装配或 `300 − M/50 − 2N/3` 秒时间路径。
7. **计分与判定**：每整秒按阵地控制给控制度（match_v1），基地被击毁立即按基地血量判胜，
   420 秒按控制度 → 攻击伤害 → 剩余血量 → 平局判定。

## 合成（SYNTHETIC）部分，非手册数据

- 场地：沿用原沙盒 12 × 7.6 m 点对称演示地图与三面墙；四个阵地矩形与目标区模式相同；
  补给区、装配区、前哨站 / 基地的位置和半径为自定。每个阵地只用一个矩形代表其全部增益点，
  未建模中央高地、堡垒、制高点、地形跨越增益点、能量机关、飞镖、雷达、空中系统。
- 机器人尺寸、最大速度、底盘峰值功率与速度的关系、弹速（低于初速上限）、射击间隔、弹道散布、
  6 m 感知距离、装配时长 15 秒 / 级、工作台在补给区内。
- AI 策略：步兵先补弹，后进攻对方前哨阵地，控制后推进对方基地，血量低于 30% 回补给区；
  哨兵守己方前哨阵地；重装先装配再装 42mm。AI 很粗糙，只为驱动规则，不代表战术建议。
- 机器人依次移动，每个 tick 交替正序 / 逆序，避免固定的先手优势；被正面堵住时侧移避让。

## 校验

- `tests/match_lab_tests.cpp`：4 种配置；两次独立运行输出逐字节一致；每个 tick 检查血量范围、
  步兵等级 = 经验对应等级且受上限约束、上限血量与性能表一致、战亡时读条长度 = 公式、
  金币 = 收入 − 支出、兑换上限、己方前哨阵地被己方完全控制时基地不掉血、基地阵地只由拥有方完全控制、
  完全控制的前哨阵地上前哨站必存活且归控制方、逐秒重算控制度与账本一致、攻击伤害账本 = 各机器人造成伤害之和；
  并确认 4 个场景合计触发全部 17 类事件。
- `tests/test_match_lab.py`：配置严格校验、CLI 确定性、帧数据与摘要输出、原生参数拒绝。
- 已一次性验证：`-O0` + AddressSanitizer/UBSan 与 `-O2` 的完整输出（含帧）逐字节一致。
