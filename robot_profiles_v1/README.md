# 2027 带出处的参数预设，不是完整官方角色

这层功能把核验过的少量参数装入原有多机器人实验场景，同时保留每个参数的来源、适用条件和工程假设。
它不实现完整官方机器人、正式阵容限制或完整 RMUC 比赛。原合成模式与原始回放格式继续使用，
`roster_mode/`、C++ 权威引擎和已有规则模块不因这层功能而改动。

## 这次能够应用哪些值

- **步兵：40 个静态组合**。两种底盘选择 × 两种发射机构选择 × 1–10 级。
  只从手册应用最大 HP、17 mm 热量上限和基础每秒冷却值。
- **重装：4 个 HP-only 快照**。只应用 400 / 450 / 500 / 600 最大 HP。
  600 对应第三次装配完成**或**模块化 42 mm 发射机构安装成功，不能误写成同时满足。
  这里不实现装配过程、42 mm 发射或重装特殊机制。
- **哨兵：2 个 HP-only 快照**。自动模式最大 HP 400，半自动模式 200。
  模式名称仅指定来源表行，不实现正式控制限制或姿态。移动姿态的冷却除以 3、取整和增益顺序
  不能直接替换为现有定值冷却，因此这次不应用哨兵热量参数。

2027 手册已将旧英雄和工程角色合并为重装，不会从旧赛季补出两个假定角色。
空中系统、飞镖、雷达等不提供可冒充地面圆盘机器人的来源预设。

**所有其他数值仍须明确提供为合成参数**：弹药库存、碰撞半径、移动速度、实际弹速、单次碰撞伤害、
发射间隔和感知范围等。规则中的弹速上限不是实际恒定弹速，底盘功率不是移动速度，发弹允许量不是
初始实体弹药库存，装甲扣血表也不是所有圆盘命中的通用标量。我们不会把这些量硬套进现有字段。

特别注意：引擎重置时把当前 HP 初始化为配置的最大 HP。这是实验初始化，不是官方升级时满血、
后期装配自动治疗，或高等级开局规则。高等级只是冻结参数快照，没有经验、升级、增益或状态转换。

## 在原多机页面使用

先照根目录 README 构建并启动，再打开 `http://127.0.0.1:8765/roster.html`。
新的参数面板将来源选择草稿与已应用运行的来源状态分开。选择表行时同时查看：

1. 哪些字段来自固定版本手册，具体页码和条件是什么。
2. 哪些字段仍是显式合成输入。
3. 哪些角色行为尚未实现，以及当前热量策略是否启用。

解析草稿不会改变比赛；应用操作才会通过原有事务性重置创建新局。配置和回放封装固定写明
`official: false` 与 `complete: false`，不能通过改标签、引用或重算校验和宣称完整官方实现。
普通原始配置重置 / 回放导入成功后，先前的来源关联会清除，即使数值恰好相同。失败不会替换原局。
来源目录不可用时，原合成模式仍应可用；页面不会保留未经验证的来源标记。

## 保存、检查和回放

来源配置是独立的版本化封装：选择条件、完整原生配置、逐字段出处、合成假设和目录身份一起保存。
来源回放在此基础上嵌入**不变的原始原生回放**。导入先重建并核对出处，再由原 C++ 引擎按记录动作
逐帧复算；不执行策略回调。原始合成回放不会仅因为数值相同就自动获得来源标记。

来源一致性不是历史认证。它不证明现实机器人满足选择条件，也不证明某策略曾生成这些动作。
所有回放仍是会暴露全体动作的开发文件，不是过滤后的选手视图或防篡改比赛记录。

本地只读命令示例：

```sh
python3 -m robot_profiles_v1 catalog
python3 -m robot_profiles_v1 example > selection.json
python3 -m robot_profiles_v1 resolve selection.json > configuration.json
python3 -m robot_profiles_v1 validate configuration.json
python3 -m robot_profiles_v1 validate-replay sourced-replay.json
```

最后一个命令检查结构和来源绑定，不代替完整仿真复算；完整复算使用页面的来源回放导入。
所有 JSON 都拒绝重复键和非有限数字。没有联网安装、外部发布或自动迁移旧原生回放。
