# RMUC Tactics Lab · 工程原型 0.1

**非官方 RMUC 2027 战术沙盒。尚未实现完整 2027 规则，不能据此评估真实比赛胜率。**

这份可运行源码验证一条最小闭环：浏览器输入 → C++ 权威仿真 → 状态与事件 → 浏览器显示 → 已解析输入回放。原战斗沙盒只有两台实验机器人和一张演示地图。原战斗沙盒数值为工程假设；新增独立目标区教学模式将真实移动连接到已有带出处的规则子模块，但适配几何、检测、控制延续和可选计分时机仍为明确标注的实验策略。

## 启动

需要 Bash、支持 C++20 的编译器（已测试 GCC 14.2）以及 Python 3.10+。没有 npm、pip 或在线编译依赖。

```bash
bash tools/build.sh
python3 server.py
```

然后在这台电脑的浏览器打开 `http://127.0.0.1:8765`。修改端口可用 `python3 server.py --port 8766`。Ctrl+C 停止。修改源码或重新构建前，先停止正在运行的服务，构建完成后再启动，避免替换运行中的可执行文件。首次下载后，macOS 或 Linux 若提示执行权限，请使用 `bash tools/build.sh`。Windows 可通过 WSL 运行；原生 Windows 未验证。

当前浏览器路径是 **原生 C++ 进程 + 本机 Python HTTP 桥接**，不是纯静态网页，也不是已经编译好的 WebAssembly。服务只绑定 127.0.0.1，不发布到公网。不应把 Python 演示服务器暴露为生产服务。

## 推荐入口：可配置多机器人战术场景

打开 `http://127.0.0.1:8765/roster.html`。新增场景默认是明确标注的**实验 2v2**，
每方可配置 1–4 台机器人，总计最多 8 台。这是可编程的合成阵容，不是官方完整阵容。
原来的双机战术场景和其他模式继续保留，状态与回放互不混用。

- 每台机器人有稳定 ID、队伍、合成参数、出生位置和目标资格标记；在页面编辑配置并重置即可应用，
  不需要修改核心代码。数组顺序不会改变动作归属，重复身份、非法参数或重叠出生点会拒绝。
- 每台独立选择人工或可信本机 C++ 策略。当前所选人工机器人接收键鼠输入，其他人工机器人保持中性输入。
  所有策略先拿到同一个 tick 的各自过滤快照，再统一执行，不能靠回调顺序看到提前更新的世界。
- 自身 HP、弹药与热量可见；其他机器人（包括队友）只在自身范围 / 遮挡条件允许时提供 ID、队伍与姿态。
  初始阵容、参数、出生点和目标区状态是明确公开的实验配置，不是当前隐藏遥测。
- 每台的热量、发射与检测宽限独立计算，再做明确的实验队伍聚合。一台队友失能不会清除另一台的有效激活。
  同刻命中先按目标汇总，再核对实际扣血并计入对方队伍，支持同刻互相失能，不虚构个人过量伤害归属。
- 沿用带出处的占领 / 控制分 / 伤害账本 / 热量 / 420 秒终局子模块，但多机几何、友方弹丸穿透、
  资格聚合、采样和事件顺序都是具名工程选择。未裁定规则边界仍会拒绝，不宣称完整官方比赛。
- 回放保存全部稳定 ID 的已解析请求动作，导入不执行策略回调，并绑定阵容、参数、规则策略与源码身份。
  这是会暴露所有输入的开发文件，不是抗作弊记录。

默认双方全 C++ 的对称示例会交换四个目标，控制分可能一直是 0:0：公式要求一队同时控制两座前哨或两座基地，
并非每占领一个目标就得分。想观察分数增长，可让一方两台保持人工且不移动，另一方两台运行策略。

编辑 `roster_mode/example_policy.cpp` 可按 `self_id` 实现不同角色。接口和信任边界见

## 保留入口：双机交火与目标争夺的一体场景

打开 `http://127.0.0.1:8765/tactical.html`。`experimental-tactical-v1` 将两台机器人、人工 / C++ 控制、移动、射击、伤害、四个目标区、控制分和 420 秒终局放在**同一局、同一个 C++ 权威世界、同一条 60 Hz 时钟**里。旧模式仍可单独使用。

开始时可保持机器人 0 人工、机器人 1 策略，或把两台都改为 C++，观察示例先占领再交火。界面有逐帧、推进 1 秒 / 10 秒和速度选择；不会跳过物理或规则 tick。机器人失能后不能移动或射击，但不会提前结束整局，也不会复活。自己的失能状态可见，敌方生命值仍不公开。

这条闭环使用已有带出处的占领与结算子模块，但**不是完整官方比赛实现**：

- 已核验子集：普通检测丢失的 2 秒宽限、完整控制到临时控制的 5 秒占领与竞争处理、控制计分公式、实际扣血的攻击 / 非攻击分类、判罚扣血归属、420 秒控制分 → 攻击伤害 → 存活机器人 HP → 平局的终局公式。
- 明确的工程适配：四个占位矩形、存活机器人中心入区作为合格检测、ceil(tick×1000/60) 毫秒采样、死亡立即清除检测激活、临时控制一次占领后锁存、不可破坏基地的正 HP 占位值。无复活、恢复、重建或正式检测卡模型。
- 默认“可玩工程预设”明确启用**计时器先于同刻输入**与**每秒末采样控制分**，先处理同刻占领，再结算该秒，包括第 420 秒。这不是已核验的官方采样时机。也可重置为严格边界拒绝或关闭计分，设置和回放都记录完整策略身份。
- 默认新增明确标注的“实验弹丸扣血核对”：逐 tick 核对对手弹丸证据与实际扣血，过量命中的名义伤害不多计，账本不公开给策略。控制分相同时可继续比较实验攻击总量、存活机器人 HP 或平局。这不是完整正式伤害系统；混合 / 未知来源不猜测，保持待裁定。也可选择“缺少已裁定账本”保留原来的同分待裁定行为。关闭计分仍只显示未计分到时结束。

默认还启用明确的17mm热量实验：只借用1级冷却优先发射机构的40热量上限和12/s冷却值，
每次实际发射事件视为检测到一发弹丸，增加10热量；每100ms精确冷却，超限锁发射直到热量归零。
**2027基线这里没有过热扣血公式，不会添加HP伤害或攻击分。** Q0+100处的正文「>」与图示「≥」冲突，
默认拒绝该未裁定边界；可明确选择实验解释，也可关闭热量。其他机器人参数仍是工程数值，
不因此变成完整官方步兵模型。只公开自身热量和热锁，俯视战术地图不是第一视角图传，不会假装断图传。

观测保留过滤对战的自身数据与敌方 6000 mm 范围 / 遮挡限制。目标区几何、控制方 / 控制程度、控制速率和总分是**特意公开的实验广播**，不是官方裁判通信声明。占领进度、检测 / 激活、失效期限、对方是否在圈内及其血量、攻击总量与扣血账本都不传入策略或普通页面。终局只显示结果和比较依据，不显示私有数值。界面不显示假进度条；只画真实公开的控制状态。

- 公开静态演示地图；自身位置、朝向、HP、弹药和冷却可见。敌方只有中心距不超过 6000 mm 且不被墙遮挡时的位置/朝向可见，永不提供敌方 HP、弹药或冷却。可见弹丸只提供位置和速度，不提供全局 ID、所有者或寿命。没有记忆轨迹、全局事件或命中统计。
- 页面只显示所选机器人的过滤视角。切换视角或控制来源会暂停并释放输入。终局通知属于单独的运行控制信息，不是策略传感器字段。可切换视角及导出开发回放的工具不是比赛反作弊边界。
- 编辑 `combat_mode/example_policy.cpp` 中的 `combat::policy::decide`，使用独立的 `policy_sdk.hpp`，再构建并重启。函数按 `observation.self_index` 区分两个机器人，可分别调用不同的自写策略。示例只依据可见目标和公开地图搜索、绕障、瞄准与射击。
- 这是**可信本地 C++**，不是执行不可信代码的安全沙箱。两个策略共享同一进程；原生代码可使用全局变量、文件或其他绕过接口的途径。仅支持无状态、只依赖快照的策略，但不强制纯函数。所称“过滤”只针对提供的观测字段，不承诺阻止恶意代码读取其他信息。
- 单步/批次错误不会提交模拟状态和日志；这不撤销自写代码的文件、网络等副作用。每次批次使用候选进程从已解析动作重建前缀，开销随历史长度增长。20 秒保护是每条原生命令的响应超时，不是实时调度或 CPU 配额。
- 新回放格式 `rmuc-filtered-combat-replay.v1` 保存双方逐 tick 的已解析输入、来源声明、过滤观测摘要和状态摘要。导入不调用策略或描述函数。回放是**会暴露双方输入的开发审计文件**，不是可交给选手的过滤视图；摘要和来源标签都不构成抗篡改或策略真实性证明。

完整接口、输入范围、传感器边界和本地用法见 [`combat_mode/POLICY_SDK.md`](combat_mode/POLICY_SDK.md)。浏览器渲染、真实指针交互和下载落盘仍未经过实际浏览器验证；已有真实 JavaScript 处理器与本机原生服务联调测试。

## 体验

- WASD / 方向键驾驶红方，鼠标瞄准，空格或鼠标左键发射。
- 红方可切换：全人工、人工驾驶 + C++ 瞄准/射击、C++ 全自动。
- 蓝方运行同一份 C++ 基线策略。当前演示策略不是强策略。
- 开始/暂停、单步、重置；窗口失焦或切后台自动暂停并清除按键/扳机。
- 回放导出保存到浏览器下载目录。导入逐帧验证后，停在最后一帧；导入失败保留当前局。
- 没有时间轴播放/快照跳转功能；“验证回放”是从零重放校验，不是可视化视频播放器。
- 移动端布局有适配样式，但尚无触屏虚拟摇杆。实际移动设备交互未验证。

## 写自己的 C++ 策略

编辑 `src/policy.cpp` 中的 `scripted_policy(const Observation&)`，返回 `Action`。重新构建并重启服务。

观察包含当前 tick、当前机器人编号和两台机器人的状态；这是明确的**全信息观测**，不是正式裁判通信/传感器接口。策略每 tick 决策，两个策略都看到相同的步进前状态。策略只能返回移动、瞄准目标和发射意图。

当前策略属于本机可信 C++ 源码，与引擎同进程。没有隔离任意导入代码，没有燃料计量，也不支持网页内编译。不要编译运行来源不明的策略。桥接层有 5 秒进程响应超时；超时导致试验无效，需要重启，不算比赛判负。

## 回放与确定性

回放记录 `sandbox-v1`、`integer-mm-v1`、引擎源码 SHA-256、逐 tick 已解析动作和逐帧状态哈希。导入拒绝不同构建、非法输入、断号帧、哈希漂移和超长文件。更改核心、方向查表或策略会改变构建 ID，旧回放须保留原构建验证。

状态哈希为固定字段顺序、小端 32 位字的 FNV-1a，仅检测漂移，不提供抗篡改/可信比赛证明。源码 SHA-256 不是编译器/二进制认证。已验证本机 GCC O0/O2 的结果一致；尚未验证跨架构、跨浏览器或 WASM。没有隐藏随机数，当前模型不使用 RNG。

## 新增：可编程机器人 C++ 策略 SDK v1

分层移动实验现在支持在「人工输入」与本地编译的 C++ 示例策略之间切换。
选择策略只决定下一批动作来源，不会重置世界；切换会暂停并释放人工按键。
示例控制器读取每个 tick 开始前的观测快照，经过坡道到达上层桥面并停止。

1. 编辑 `layered_mode/example_policy.cpp`，实现 `descriptor()` 和 `decide(const Observation&)`。
2. 仅依赖公开头文件 `layered_mode/policy_sdk.hpp`，返回版本为 1 的整数方向动作。
3. 运行 `bash tools/build.sh`，重启 `python3 server.py`，打开 `/layered.html` 并选择 C++ 策略。

策略和人工动作进入同一个原生动作校验器。SDK 提供拥有独立存储的只读观测，明确包含完整测试几何，
不是正式传感器可见性模型。回放 v2 保存最终采用的动作和来源记录；回放导入接口只重算动作，不调用决策或描述器回调。
页面随后刷新当前策略信息时，仍可能在独立候选进程调用描述器；这与重放决策是两回事。
历史来源标签未经认证，不能证明某个策略实际生成了这些动作，也不证明任意用户策略具有确定性。
旧的 v1 分层回放需要保留原源码版本验证，不能直接混用。

**这不是不可信代码沙箱。** 策略是本机原生 C++，可以访问文件、网络和进程；不要编译运行来源不明的代码。
候选进程与超时检查保护的是当前仿真状态，不能撤销或隔离代码对外部环境的副作用。
初版只支持无状态策略；每批策略执行要重算已有动作前缀，较长运行可能变慢，没有实时性能承诺。
观测契约、动作校验、失败语义、版本/源码身份和完整示例见 [策略 SDK 说明](layered_mode/POLICY_SDK.md)。
