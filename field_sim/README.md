# 官方场地仿真（field_sim，`rmuc2027-field-sim-v1`）

在 **1:1 复刻的 RMUC 2027 官方场地**上运行机器人的独立模式。场地来自官方开源 STEP 模型，
机器人力学是明确标注的 2.5 维工程模型。它与仓库里其它模式互不共享状态、回放和构建 ID。

```bash
bash tools/build.sh
python3 server.py            # 浏览器打开 http://127.0.0.1:8765/field.html
```

页面里用 WASD 平移、Q / E 旋转、鼠标控制云台指向；点击机器人切换操控对象；
光标移到场地上可以读出该处的地面高度、上方结构净空和所在增益点。

开发计划见 [docs/PLAN.md](../docs/PLAN.md)：本目录目前完成的是第 1 项（场地），
车辆配置与车库、对外感知 / 控制接口在后两项加入。

## 场地数据从哪里来

| 内容 | 来源 |
|---|---|
| 地形高度、墙体、坡道、台阶、隧道、道具占位 | 官方 `RMUC2027_V1.0.0.stp`（653 MB，MD5 `3d3d6a41…0bf7`，[发布帖](https://bbs.robomaster.com/article/1970956)） |
| 外廓 28 m × 15 m、公差、中心对称 | 规则手册 §4.1 |
| 基地 / 前哨站轴线位置 | 手册图 4-5 |
| 增益点（场地交互模块卡）范围 | 手册图 5-23，红方取图、蓝方中心对称 |
| 地形跨越增益点的高 / 低、隧道内部 | 手册 §5.6.4.5 + 提取出的高度 |

STEP 文件太大，不放进仓库；地址、大小、MD5 / SHA-256 记录在
[`field/rmuc2027_v1/provenance.json`](field/rmuc2027_v1/provenance.json)。
提取流程可以用 [`tools/field_extract/`](../tools/field_extract/) 重跑（只在开发时需要，依赖 OpenCASCADE 的 Python 绑定和 numpy；
**构建和运行仿真不需要它们**）：

```bash
pip install cadquery-ocp numpy
python3 tools/field_extract/extract_step.py RMUC2027_V1.0.0.stp cache/      # 约 3 分钟、5 GB 内存
python3 tools/field_extract/build_terrain.py cache/ field_sim/field/rmuc2027_v1
python3 tools/field_extract/build_field_json.py cache/ field_sim/field/rmuc2027_v1
```

1. **读模型**：按装配关系展开 81 个部件实例，三角化（弦高 1 mm）得到 559 万个三角形，
   并记录每个三角形属于哪个封闭实体或开放曲面。
2. **定坐标系**：拟合战场地面的两个斜面，交线就是场地长中轴线。由此得到战场坐标：
   x 沿 28 m 长边、从红方底线指向蓝方；y 沿 15 m 宽边（y 朝上时红方在左，和手册俯视图一致）；
   z 向上，中轴线处地面为 0。
3. **采样**：每个 20 mm 网格中心作一条竖直线与全部三角形求交。封闭实体按进出次数累计得到实心区间
   （同时完成重叠实体的合并），开放曲面取它在该格的竖直包络。间隙小于 60 mm 的区间合并。
4. **分层**：每格记录“与地面相连的表面高度”（ground），如果上方还有悬空物体（隧道顶、桥、能量机关），
   再记录最低一个悬空物体的下表面和上表面（overhang）。下方净空不足 100 mm 的空腔按实心处理。

结果是 [`terrain.bin`](field/rmuc2027_v1/terrain.bin)（1400 × 750 格，2.3 MB）和
[`field.json`](field/rmuc2027_v1/field.json)（38 个功能区、7 个结构、8 个出生位姿）。

原生测试还检查了中心对称：每隔 5 格抽样 42000 格，与对称位置相差超过 6 mm 的不到 1%（来自道具摆放姿态等细节）。

### 没有做或做了简化的地方

- 每格只保留一个悬空层；它上方更高处的物体不表示。
- 基地、前哨站、能量机关、飞镖发射站、能量单元等道具按模型里的静止姿态当作实心地形，
  不会转动，也还没有装甲和血量（第 3 项接入）。
- 围挡在模型里没有建模：场地边界一律当作不可越过的墙，弹道 / 视线到边界即止。
- 增益点轮廓来自 25 mm / 像素的手册插图，精度约一个像素；隧道内部的卡按两端卡之间的带状区域处理。
- 出生位姿是在启动区内自行选定的 8 个点，手册只规定机器人放在启动区。
- 模型自身的说明同样适用：它“仅做参考”，与手册或现场不一致时以后者为准。

## 引擎模型（工程假设）

固定 100 Hz。每个 tick：底盘驱动与碰撞 → 机器人之间的碰撞 → 竖直运动与姿态 → 云台 → 裁判系统功率结算 → 增益点检测。

- **碰撞体**：竖直圆柱（默认半径 0.33 m），因此原地旋转不会被卡住。沿圆周每 20 mm 取一个探测点。
  探测点处的地形如果比车底高出越障高度、并且在 40 mm 内突然升高，就是墙；
  上方有顶而净空小于车高，也是墙。被挡住时沿障碍物切向滑动。
- **坡与台阶**：坡道随高度场爬升；不超过越障高度（默认 30 mm）的台阶可以直接上去，
  更高的要靠坡道，或者换一台越障能力更强的车。从台地边缘可以直接驶下。
- **腾空**：地面“下落”得比自由落体快时机器人离地，按重力下落直到重新接触地面；
  离开坡顶时保留沿坡向上的速度，所以可以飞坡。腾空时没有牵引力。
- **隧道与分层**：机器人轮底高于某格悬空层的下表面时站在它的上表面，否则在它下面的地面上，
  所以既可以从隧道里穿过，也可以从上面跨过。只有在顶下面时才会读到“隧道内部”的卡。
- **驱动**：指令是底盘系或云台系下的前向 / 侧向速度和角速度；受最高速度、加减速度、角加速度限制。
  差速 / 平衡底盘不能横移。
- **功率**：电功率 = 待机 + 机械功率 / 效率 + 与牵引力平方成正比的损耗。车载限制器（可关闭）
  把功率压在“上限 + 超级电容 + 缓冲能量余量”之内。电池侧功率每 100 ms 结算一次，
  由规则模块 [`limits_v1`](../rules/rmuc2027_limits_v1/README.md) 按 §5.1.4 扣缓冲能量、耗尽后断电 5 秒。
  功率上限暂为固定 80 W，第 2、3 项改为按兵种 / 等级查表。
- **云台**：场地系下的偏航（默认滑环、可连续旋转）和相对水平面的俯仰；角度或角速度指令，
  受最大角速度、角加速度和相对车体的机械限位约束；自稳，底盘旋转不带动云台。
- **增益点**：机器人中心落在卡的多边形内、且没有腾空，即视为检测到。这是几何判断，
  不是官方 RFID 检测模型；增益效果在第 3 项接入。

没有模拟：轮胎与悬挂、侧翻、车体与地形的精确外形碰撞（用的是圆柱）、撞击伤害、战场倾斜导致的弹丸滚动。
数值使用双精度浮点，同一份二进制重复运行结果逐字节相同；不承诺跨平台逐位一致。

## 本机接口

引擎是一个逐行 JSON 的本地进程（`build/rmuc_field`），`field_sim/bridge.py` 负责启动它、
核对构建 ID、在候选进程接受新对局之后才替换当前对局。HTTP 接口只绑定 127.0.0.1：

| 接口 | 说明 |
|---|---|
| `GET /api/field/meta` | 模式、构建 ID、`field.json` 全文、当前与默认对局 |
| `GET /api/field/terrain` | `terrain.bin` 原始字节 |
| `GET /api/field/state` | 当前全部机器人状态（观察者视角，不是机器人自己的感知） |
| `POST /api/field/reset` | `{"robots":[{"id":"R1","team":"red"},…]}`，每队至多 4 台 |
| `POST /api/field/step` | `{"ticks":1..200,"commands":{"R1":{…}}}`；指令保持到被替换 |
| `POST /api/field/probe` | `{"x":…,"y":…}`（米）→ 该处地形与区域 |

指令格式（单位：米、弧度、秒）：

```json
{"chassis": {"vx": 2.0, "vy": 0.0, "wz": 1.5, "frame": "chassis"},
 "gimbal": {"mode": "angle", "yaw": 0.6, "pitch": 0.05},
 "supercap": true}
```

`gimbal.mode` 为 `hold` / `angle`（场地系偏航、相对水平面的俯仰）/ `rate`（`yaw_rate`、`pitch_rate`）。
未知的键、越界或非数字的值会被拒绝，当前对局不变。

`terrain.bin` 格式（小端）：8 字节 `RMTERRN1`；5 个 int32：列数、行数、格子边长 mm、悬空格数、保留；
列数 × 行数个 int16 地面高度（mm，行按 y 从小到大）；悬空格的 uint32 格子序号、int16 下表面、int16 上表面各一组。

## 测试

- `tests/field_sim_tests.cpp`（74,177 个断言）：JSON 解析；合成地形上的分层、插值与射线；
  官方场地的尺寸、高度、对称、视线、功能区与出生点；加速 / 功率 / 断电 / 超级电容；墙、台阶、坡道、低顶、
  驶下台地、飞坡；差速底盘；云台跟踪与限位；机器人互撞；官方场地上的沿墙滑行、上坡、穿隧道读卡顺序；确定性。
- `tests/test_field_bridge.py`：场地数据与来源记录一致性、对局校验、拒绝不改变状态、过期二进制被拒绝。
- `tests/test_field_http.py`：HTTP 接口与各拒绝路径。
- `tests/field_browser_smoke.cjs`：真实浏览器里加载页面、驾驶机器人、读取地形（可选，需要 Playwright）。
