# 独立激活延迟与占领子模块

版本：`rmuc2027-capture-v1.0.0-module.1`。C++20，无第三方依赖。
**不是完整占领/裁判模拟器，也没有接入沙盒、单局结算模块或场景工具。**

依据为 RMUC 2027 中文比赛规则 V1.0.0（2026-10-15），印刷页 94、96、102
（PDF 物理页 95、97、103）。[官方资料页](https://bbs.robomaster.com/wiki/20204847/1969149?source=7)。
原始 PDF 链接、SHA-256、审计矩阵身份、完整相关行与逐项实现边界见
[provenance.json](provenance.json)。尚未核验最新官方答疑，不能将工程选择当官方细则。

## 三个互相独立的接口

- `ActivationDelay`：一个**已通过资格判断的检测信号轨道**。从普通检测丢失开始，
  逻辑激活延后 2000 ms 失效；同一轨道在到期前重新检测会取消待失效事件。
  `Present` 表示检测已发生，不是机器人进入几何区域。初始 `Absent` 不产生虚构宽限期。
  不处理交互卡切换、多机器人汇总、死亡、弱化、强制增益失效或资格变化。
- `CaptureAttempt`：一处已裁定为 `Full` 的阵地，接收双方**整处阵地已裁定的逻辑激活状态**。
  对当前完全控制方的对手累计占领进度；未满 5000 ms 时失去逻辑激活等速回退到零；
  双方激活则暂停，单方恢复后继续增长或回退。下游不再加 2 秒。
  达标后只产生对手 `Temporary`，此占领尝试结束。不会启动失控恢复时钟。
- `map_qualified_transition`：表 5-21 四行的**无状态字面映射**，消费外部已经裁定的
  占领阈值达成、暂控方连续不激活 5 秒或指定一方击毁前哨站事实。
  不自行证明时长、命中、机器人资格或前哨是否存活。
  首个事实 `AdjudicatedCaptureThresholdReached` 必须已应用共享竞争/进度备注，
  不能仅凭某方连续检测 5 秒忽略竞争；恢复事实也必须已排除未定边界。

原始阵地拥有方、当前控制方、控制程度分别保存；没有将前哨对象归属混入这些字段。
基地只能由初始拥有方完全控制。暂控方失去控制的表格映射指向**当前暂控方的对手**，
不擅自选初始或上一次完全控制方。

前哨击毁的两种映射分别为：敌方击毁 `Full(A)` 得到 `Temporary(A)`；
`Temporary(A)` 下由 A 击毁得到 `Full(A)`。不支持的行动方/状态组合直接报错。
所有击毁映射以及前哨阵地的连续缺席恢复映射均输出
`requires_external_outpost_lifecycle_adjudication=true`。
这只说明控制表格的结果，**不证明前哨能再次被击毁，不产生重建、500 HP 或存活状态**。
外部必须单独裁定生命周期；本模块不能验证一串孤立映射构成合法比赛过程。
该标记为 `false` 也不证明前哨存活、重建或生命周期合法，只表示该映射未额外标记此义务。

## 时间、结束与原子性契约

使用非负 `int64_t` 毫秒，是精确输入时间线的工程表示，不是官方采样分辨率。
初始化时刻已关闭；每次 `apply(t, optional_input)` 的 t 必须严格增加。
一次输入是已裁定的完整快照/单一检测边沿，没有同刻顺序事件列表。
不允许先 `apply(T)` 再补交同刻输入，避免绕过歧义检查。
同值重复边沿拒绝；不会偷偷重启宽限。非法时间、枚举、溢出或不支持路径不改变状态和轨迹。

`CaptureAdvance` 返回 `state.time_ms`（实际消费终点）、`requested_time_ms` 与
`unconsumed_ms`。例如持续逻辑激活时请求推进到 6000，结果为在 5000 暂控、剩余 1000。
**调用方必须接管剩余区间**；模块没有消费它、没有恢复控制或计分。
完成后的实例拒绝继续推进。若输入位于完成终点之后，整个调用拒绝，绝不丢弃输入。
无需输入的长步进与等效短步进，在支持的区间产生相同状态、语义轨迹与剩余时间。

默认 `StrictRejectUnadjudicated` 在以下情况显式失败：

- 重新检测与 2 秒宽限到期同刻。
- 逻辑输入变化与 5 秒占领达标同刻，包括 3 秒检测激活后丢失、再经过 2 秒宽限。
- 双方激活直接变为双方均不激活。表格“直到仅剩一方”与一般回退文字不能替此路径定序。
- 对 `Temporary` 状态请求自动计时。连续缺席时钟与共享暂停/回退备注的关系尚未闭合。

仅同刻计时/输入顺序可显式选择 `EngineeringTimerBeforeInputV1`：先到期，再输入。
该模式没有“官方”含义，轨迹逐条写入
`ENGINEERING-NOT-OFFICIAL-timer-before-input-v1`，实际采用时额外产生策略事件。
它不放开双方直接离场、恢复计时或生命周期缺口。默认模式不会自动切换到此策略。

每个对象内部失败是原子的，**跨对象原子性由调用方负责**。组合时须先复制两个对象，
按逻辑事件的实际时间把激活输出交给占领端，全部成功后再一并提交。
不能先提交实时激活对象，再因占领端拒绝而声称整体未变。
`demo.cpp` 和测试给出一个单轨道的事务例子，不提供多机器人/多卡汇总器。
如果一个长输入区间内有多个逻辑边沿，调用方必须逐个交付，不能只拿末尾布尔值。

轨迹只记录有语义的边沿/边界，不为无事件的查询采样加条目，所以不依赖调用分段。
这些是内存中的 C++ 值，没有改变现有场景日志格式，也没有创建新持久化回放格式。
若后续适配器保存轨迹，必须保存模块版本、手册 SHA-256、完整输入及策略名；不能当作
官方认证、二进制认证或防篡改签名。

## 构建与验证

在项目根目录：

```bash
bash tools/build.sh
./build/capture_rule_tests
./build/capture_rule_property_tests
./build/capture_rules_demo
bash tools/check.sh
```

测试覆盖表格四行、基地限制、5 秒与 2 秒的前/正好/后边界、宽限内重新检测、回退、
暂停、剩余区间、严格/显式工程同刻策略、输入错误、溢出、状态及轨迹的原子拒绝、
重复执行和时间分段一致性，以及跨组件事务的 3+2 秒反例。
另附独立审阅者的固定种子属性测试（`tests/capture_rule_property_tests.cpp`，seed 412），
检查随机输入下的分段一致性、结果一致性及极限整数。它不是独立的官方规则判定器。
只有 C++ 单元/合成场景，没有物理传感器、裁判实机、真实对局或跨平台一致性验证。
