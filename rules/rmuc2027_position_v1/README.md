# RMUC 2027 阵地控制生命周期模块 v1

`rmuc2027-position-v1.0.0-module.1`。依据固定手册 [`docs/rules/`](../../docs/rules/README.md)。

这是原 `rmuc2027_capture_v1` 刻意没有实现的部分：临时控制之后怎样恢复，以及前哨站被击毁后的控制转换与重建。
输入是每方对阵地任一增益点的**逻辑激活**（2 秒失效延迟由上游，例如 capture_v1 的 `ActivationDelay` 处理）。

## 表 5-21 四种转换

| 转换 | 条件 | 本模块 |
|---|---|---|
| 对方完全控制 → 己方临时控制 | 己方连续激活 5 秒；未满 5 秒离开时进度均匀倒退；双方同时激活时暂停 | `CapturedTemporary` |
| 对方临时控制 → 己方完全控制 | 对方连续 5 秒不激活 | `RevertedFull` |
| 对方完全控制的前哨阵地 → 对方临时控制 | 击毁阵地上的前哨站 | `DestroyedToTemporary` |
| 己方临时控制的前哨阵地 → 己方完全控制 | 击毁阵地上的前哨站 | `DestroyedToFull` |

- 开局双方各完全控制己方前哨阵地与基地阵地；基地阵地只有初始拥有方能完全控制（表 5-20）。
- 前哨站由一方完全控制转为另一方完全控制时，重建为新控制方的前哨站，500 血（§5.6.1 p94），事件里 `rebuilt = true`。
- `full_by(team)` 用于判定基地 100% 防御（己方前哨阵地被己方完全控制）。

## 工程选择 / 未决

- “连续 5 秒不激活”的计时在临时控制方任一时刻激活时清零，不倒退（倒退规则只写在激活占领一行）。
- 前哨站被击毁后己方仍为临时控制、随后因己方离开 5 秒而由对方完全控制时，也视为“通过击毁方式”转换，前哨站为对方重建。
- 转换发生在 5 秒恰好累计满的那一毫秒；同一调用内时间按上一次给定的激活状态流逝。

## 测试

`tests/position_rule_tests.cpp`：四种转换、倒退 / 暂停、恰好 5 秒、长区间、基地只能由拥有方完全控制，
以及 12 万步随机序列不变量（完全控制的前哨阵地上前哨站必为控制方所有且存活等）。
