# RMUC 2027 V1.0.0 · 单局结算公式模块

模块版本：`rmuc2027-match-v1.0.0-module.1`。

这是独立的、带出处的 C++20 规则片段，不是完整赛制/裁判实现，也**没有接入现有浏览器沙盒**。原沙盒的 100 HP、演示地图和 120 秒结束条件保持不变。

## 已实现边界

1. `control_rate()`：消费上游已裁定的四处阵地控制权。控制两个前哨阵地得 1 点/秒，控制两个基地阵地得 3 点/秒，可相加。临时/完全控制都符合文本里的“控制”。敌方不得完全控制基地阵地。出处：§5.6.2，印刷 p96–97。
2. `ExternalControlLedger`：对上游提供的、已经解决时间语义的“一秒计分事件”应用上述公式，验证序号并避免重复入账；`seal()` 后拒绝加分。它**不产生计分事件**，没有秒边界/亚秒积分/余量规则。不能仅凭此账本声称计时计分已符合官方实现。
3. `evaluate()`：以已结算的边界快照判断单局结果。任一基地被毁优先；双方基地都存在且 420 秒耗尽时，依次比较控制度、攻击伤害、存活机器人当前 HP 总和；完全相同为平局。完好的基地 HP 高低不是超时判据。出处：§5.8，印刷 p114–115；§6.6，印刷 p121。
4. `surviving_robot_hp()`：仅累计主控模块正常连入、当前 HP > 0 且未被罚下的机器人。排除基地、前哨、异常离线、战亡和被罚下对象。拒绝重复实体 ID、负值和整数溢出。出处：§2，印刷 p16、p19。上游负责每个正式计分实体只出现一次，避免组合系统重复建账。
5. `MatchJudge`：拒绝时间回退；验证失败不修改记录；首次终局后保存不可再写的结算快照。它不自动驱动或封存另一个控制账本，集成层须在同一终局事务中封存相关账本。

每个 `Decision` 包含所用规则 ID。`provenance.json` 保存所用矩阵行、覆盖范围、原始文档哈希及页码。

## 必须由上游提供，不能猜的事实

- 四处阵地的已裁定控制权。物理接触不是控制权；5 秒占领、2 秒失效延迟、同时激活、前哨重建都不在本模块中。
- 完整攻击伤害账本。手册定义包含弹丸、飞镖、空中冲击以及对方违规判罚扣血，排除普通碰撞和模块离线扣血。这里不从 HP 差值推导攻击伤害。专项飞镖群体扣血归属仍有待核验项，未解决时应传空值。
- 所有同时间戳的事实已按有效裁定结算。本模块不规定控制变化/加分/基地受击的同刻优先级。
- 上游必须提供 0–420000 ms 的精确结算边界。超过正式时限的快照被拒绝，以免把赛后变化混入结算；毫秒是工程接口单位，不是官方采样频率。倒计时显示的手册偏移约定未在此实现。

控制度、伤害和存活 HP 使用可缺失字段：只有结果确实需要某个判据时，才要求其已解决。例如控制度已分胜负时，不会强制依赖尚未解决的伤害归属；控制度打平且伤害缺失时返回明确错误。

## 明确未解决/未实现

- 每秒控制计分的首个时刻、全局秒/占领后秒、亚秒余量、边界事件顺序未由手册完整规定。这里没有暗选一种实现。
- 若快照中双方基地同时为零，默认返回 `UnresolvedSimultaneousDestruction`。只有上游明确设置 `simultaneous_destruction_resolved=true`，才按 §5.8 的首条比较及末条兜底输出平局。此标记不能证明真实裁判会接受该并发快照。
- 判负、重赛、赛后改判等裁判路径未实现。任何非空 `RefereeRuling` 返回 `UnsupportedRefereeRuling`，不会假装普通比较能替代裁判。尤其不能把赛前判负的 1680 控制度套用于赛中判负。出处：§7.1.2，印刷 p125。
- BO3/BO5 平局后立即加赛属于系列赛管理，不在单局判断器里。
- 最新官方答疑、制作规范、通信协议未因增加此模块而自动完成核验。

## 构建与演示

在项目根目录执行：

```bash
bash tools/build.sh
./build/match_rule_tests
./build/match_rules_demo
```

演示输入：时间耗尽，红基地 9000 HP / 控制度 10，蓝基地 1000 HP / 控制度 11。输出蓝方胜，规则 `victory.conditions.2`。

这只展示结算公式，不模拟这些数值如何产生。完整项目验证仍使用 `bash tools/check.sh`。

## 独立场景适配器

`../../scenario_harness/` 现在提供 JSON 场景 CLI 与版本化事件日志，消费此模块的原有 API；
模块语义和版本未修改，浏览器沙盒仍未接入。该适配器显式区分外部控制总分与手工一秒
credit，按人工明确的边界顺序进行事务提交/回滚，在终局同一事务中封存账本。详见其 README
和 FORMAT；不要将可回放的人工事实误认为已验证的真实裁判记录。
